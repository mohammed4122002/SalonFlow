# المرحلة 3: نظام الحجز

## مسار العميل (`/salons/[slug]`)

1. تختار العميلة الخدمة، ثم الأخصائية (أو «أي أخصائية متاحة»)، ثم يومًا من الأيام الـ14 القادمة، ثم وقتًا.
2. المواعيد تأتي من `get_available_slots`، وتُحسب في قاعدة البيانات:
   - ساعات الأخصائية الخاصة إن وُجدت، وإلا ساعات الصالون.
   - خطوة 15 دقيقة، ويجب أن تنتهي الخدمة قبل نهاية الفترة.
   - تُستبعد الحجوزات النشطة (بانتظار التأكيد أو المؤكدة) والإجازات والأوقات الماضية.
3. الاسم ورقم الهاتف والبريد الإلكتروني إلزامية، ويُتحقق منها في المتصفح والخادم وقاعدة البيانات.
4. يُنشأ الحجز بحالة **بانتظار التأكيد** (`pending`)، وتنتقل العميلة إلى صفحة الحجز `/bookings/[token]`.

## صفحة الحجز `/bookings/[token]`

- الرابط يحتوي رمزًا عشوائيًا (UUID) خاصًا بالحجز، ويصل للعميلة بالبريد. لا تحتاج حسابًا.
- تعرض الصفحة حالة الحجز وتفاصيله.
- يمكن للعميلة الإلغاء ما دام الحجز بانتظار التأكيد وقبل موعده، فيتحرر الموعد فورًا.

## لوحة الصالون: الحجوزات

- يستطيع صاحب الصالون **تأكيد** الحجز أو **إلغاءه** مع ذكر سبب اختياري.
- عند كل تغيير:
  - يُرسل بريد للعميلة.
  - يُرسل إشعار Webhook إلى n8n إن كان مضبوطًا (راجع المرحلة 5).
- الحجوزات القادمة من البوت تظهر عليها عبارة «عبر البوت».

## منع التعارض والتزامن

- قيد `exclusion constraint` (btree_gist) يمنع تداخل حجزين نشطين لنفس الأخصائية. هذا هو الضمان النهائي حتى مع الطلبات المتزامنة.
- `create_booking` يتحقق قبل الإدخال من: الصالون (منشور، نشط، اشتراكه صالح)، والخدمة، والأخصائية، وساعات العمل، والإجازات، وأن الوقت يقع على خطوة 15 دقيقة.
- أي تعارض يظهر كرسالة واضحة: «هذا الموعد لم يعد متاحًا».
- الحد الأقصى 3 حجوزات بانتظار التأكيد لكل رقم هاتف، للحد من الإزعاج.
- تُوحَّد أرقام الهواتف (حذف المسافات والرموز)، ويُربط العميل بالصالون عبر رقمه.

### رموز الأخطاء (من قاعدة البيانات)

| الرمز | المعنى | HTTP في الـ API |
|---|---|---|
| `SALON_UNAVAILABLE` | الصالون غير منشور، أو معلّق، أو انتهى اشتراكه | 403 |
| `SERVICE_UNAVAILABLE` | خدمة غير موجودة أو موقوفة أو لا تقدمها الأخصائية | 422 |
| `SLOT_UNAVAILABLE` | الموعد محجوز أو خارج ساعات العمل | 409 |
| `TOO_MANY_PENDING` | 3 حجوزات معلّقة لنفس الرقم | 429 |
| `INVALID_CUSTOMER` | اسم أو هاتف أو بريد غير صالح | 422 |
| `INVALID_DATE` | تاريخ خارج المدى (اليوم حتى 90 يومًا) | 422 |
| `NOT_FOUND` / `NOT_CANCELLABLE` | حجز غير موجود أو لا يمكن إلغاؤه | 404 / 409 |

## البريد الإلكتروني

يُرسل عبر Resend HTTP API، **بعد** إرسال الرد للمستخدم (`after()`)، فلا يبطئ الحجز.

| الحدث | المستلم |
|---|---|
| طلب حجز جديد | العميلة، والصالون (على بريده في الإعدادات) |
| تأكيد الحجز | العميلة |
| إلغاء الحجز | العميلة |

إذا لم تُضبط `RESEND_API_KEY` و`EMAIL_FROM`، يتخطى النظام الإرسال ويسجّل سطرًا في السجل بعنوان مخفي (مثل `re***@example.com`)، ولا يفشل الحجز.
