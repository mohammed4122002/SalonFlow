# المرحلة 4: الاشتراكات

## القواعد

| الحالة | المعنى | ظهور الصالون والحجز | تعديل البيانات |
|---|---|---|---|
| `trialing` | فترة تجريبية 30 يومًا تبدأ تلقائيًا عند إنشاء الصالون | نعم، ما دامت `trial_ends_at` في المستقبل | نعم |
| `active` | اشتراك مدفوع | نعم، حتى `current_period_end` | نعم |
| `suspended` | انتهت التجربة أو الاشتراك، أو علّقه المدير | لا: الصالون مخفي والحجز والـ API مرفوضة | لا (قراءة فقط) |
| `past_due` / `cancelled` | محجوزة لبوابة الدفع لاحقًا | لا | لا |

- القرار في قاعدة البيانات نفسها (`private.subscription_valid` و`private.salon_is_operational`)، فلا يمكن تجاوزه من الواجهة أو الـ API. الإيقاف يسري فور انتهاء الوقت، حتى قبل تشغيل المهمة الدورية.
- مهمة `pg_cron` باسم `salonflow-expire-subscriptions` تعمل كل ساعة، وتسجّل الحالة `suspended` للاشتراكات المنتهية.
- عند الإيقاف يبقى بإمكان صاحب الصالون:
  - تسجيل الدخول وعرض بياناته وحجوزاته.
  - **إلغاء** الحجوزات القائمة، ليبلّغ العملاء.

  ولا يستطيع: التأكيد، أو تعديل الخدمات والأخصائيات والساعات والإعدادات، أو توليد مفاتيح الربط.
- صاحب الصالون لا يستطيع تعديل اشتراكه بنفسه. المدير العام فقط يمكنه ذلك.
- كل تغيير في الاشتراك يُسجّل في `subscription_events` (من، ومتى، والحالة قبل وبعد).

## الواجهات

- `/dashboard/[id]/subscription`: الحالة الحالية، وتاريخ الانتهاء، والأيام المتبقية، وسجل التغييرات.
- شريط تنبيه أحمر أعلى لوحة الصالون عند الإيقاف، وتُعطَّل أزرار الحفظ.
- `/admin`: إحصاءات الاشتراكات (تجريبي، مدفوع، منتهٍ)، ولكل صالون «إدارة الاشتراك»:
  - تمديد التجربة بعدد أيام.
  - تفعيل اشتراك مدفوع لعدد أشهر مع اسم الباقة.
  - تعليق الاشتراك.

## التجهيز للدفع (بدون بوابة)

- الجدول `subscriptions` فيه الحقول `payment_provider` و`provider_customer_id` و`provider_subscription_id`.
- الجدول `payments` جاهز لتسجيل المدفوعات. للقراءة فقط من التطبيق، ويُكتب لاحقًا من الخادم عبر Webhook البوابة.
- عند اختيار بوابة (Stripe أو PayPal أو غيرها) يُضاف مسار Webhook على الخادم يحدّث `status` و`current_period_end`، وتعمل بقية القواعد كما هي.
